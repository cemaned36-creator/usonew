# Главный корпус: модель маршрутов

Источник: четыре плана этажей и уточнения пользователя от 25.10.2026.
Все 67 учебных аудиторий привязаны к соседним коридорам; положение дверей
приблизительное. Спорткомплекс — отдельное помещение вне графа.

Верхний коридор около 158 м, боковые около 95 м, нижние около 58 м.
Все девять лестниц соединяют соседние этажи 1–4. На первом этаже
разорваны оба боковых крыла, на втором — правое. Прямых ребер через
разрывы нет. Вход/охрана спроецированы на центр холла первого этажа.

Скорость по коридорам — 60 м/мин; между соседними этажами — 30 секунд.
Кратчайший путь ищется по времени. Полный участок округляется вверх до
целой минуты (минимум 1 между разными помещениями). Ключевые операции
сервис добавляет отдельно: 5 минут получить, 5 минут вернуть.

`distance` после миграции — горизонтальные метры вдоль выбранного пути;
длина лестничных маршей неизвестна и не включена. Предпочтение близости
ко входу ранжирует комнаты по времени ходьбы, чтобы учитывать лестницы.
Это расчет по топологии здания с приближенными размерами, не результат замеров.

Повторная сборка SQL: `python scripts/build_main_building_routes.py` из backend.
Скрипт не подключается к БД. Миграция сверяет 67 имен/этажей и 4556
направленных связей, сохраняет исходные данные в `route_migration_backups`,
меняет только расстояния/время, название здания и охраны. Расписание не меняется.

Порядок развертывания: совместимый код → проверка миграции на ветке Neon →
миграция production → проверка предварительного просмотра обеих недель.
Отдельный rollback SQL восстанавливает прежние поля, если после миграции
их никто не изменял; резервная запись сохраняется. Повторное применение
миграции блокируется до ручной проверки истории.
